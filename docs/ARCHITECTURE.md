## 一句话

分层 TS 模块内核（three.js r180 + 自研模拟/渲染/音频/UI，共 173 个 `.ts`） + 一层可写的 TS 数据与扩展层；
构建时用 `vite-plugin-singlefile` 重新压回一个 HTML。`starfall.core.ts` 为 435 行薄入口，仅做 import 装配 + 2 个 glue 函数。

## 关键设计（值得复用的思路）

1. **表现与规则分离**：模拟内核用命令（`cast/move/stop`）驱动，渲染只读状态；所以能跑 200 局自动测试。
2. **技能是"规格 + 通用结算"**：`Oa` 描述伤害类型/控制/位移/自身 buff，结算层统一执行，特效和音效按事件名挂接。
3. **资源是"规则"而非"数据"**：模型用参数化几何 + 顶点色；贴图是 40 张 canvas 现画的 sprite；音效是波表合成。
4. **注册表化**：模型、特效、音效、图标、技能规格都是 `key → 实现` 的字典，天然可扩展，也是本次能拆成 TS 的前提。

## 本次反混淆的 4 处改动（其余逐字符一致）

1. 头部 `import HERO_DATA from "../heroes/index"`；
2. `kr = [...]` + `Se = {…}` → `kr = Object.keys(HERO_DATA)` + `Se = Object.assign({}, HERO_DATA)`；
3. 末尾 `export { … }`，导出 `Se/Oa/Gx/Pb/ED/FS/XB/ln` 与技能规格构造器；
4. `Oa` 之后追加 `__defaultActionSpec(id)`：给没有手写规格的英雄按数据自动生成兜底规格（只影响非内置英雄）。

校验：把 1–3 还原后与线上 bundle 比对，逐字符一致；第 4 处是新增，不改动任何内置英雄行为。

## 常见改造点

| 想做 | 改哪 |
|---|---|
| 调英雄数值/冷却/文案 | `src/heroes/<id>.ts` |
| 改技能伤害/控制/位移 | 内核 `Oa`（或写自己的规格） |
| 换/加外观 | 内核模型 builder + `Gx` |
| 加特效 | `Pb` / `ED` |
| 加音效 | `FS` + `ET/AT` |
| 调音色合成器 | 内核音频引擎段（波表/噪声/混响参数） |
| 改画质/后处理 | 内核渲染段（bloom、调色 quad、阴影档位） |
| 改 UI/HUD | `.sf-*` 样式与 DOM 构造段 |
| 改经济/兵线/野怪 | 内核开头常量 `Y6/K6/yr/rn` |
